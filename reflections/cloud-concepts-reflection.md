
# Cloud Concepts Reflection

## Cloud Services I Use

Three cloud services I use almost every day are Google Drive, Reddit, and Google Online tools.

Google Drive is where I store and share files. Instead of saving everything on my device, the files live on Google's servers, and I can open them from any device as long as I have internet. This is a Software as a Service (SaaS) setup because I just use the application — I do not manage any servers or software underneath it. It is a Public Cloud service because Google runs it and anyone can sign up for an account.

Reddit is a platform where people post questions, share links, and discuss topics in communities. I use it mainly to follow tech forums where people talk about programming and software issues. All the posts, comments, and communities are stored and served from Reddit's servers. This is SaaS because I just use the site — I do not set up or manage anything behind it. It is a Public Cloud service because Reddit runs it and anyone can access it.

Google's online tools — like Google Docs, Slides, and Sheets — are what I use for schoolwork. I can write, edit, and share documents without installing any software. Everything is saved on Google's servers and I can access it from any device. This is SaaS because I only use the tools, not the systems running them. It is a Public Cloud service because Google makes it available to everyone.

## Git and GitHub for Cloud Projects

When working on cloud projects, many things can go wrong if there is no system to track changes. You might overwrite something that was working, or two people on a team might change the same file at the same time and cause conflicts.

Git solves this by keeping a full history of every change made to a project. You can always go back to an earlier version if something breaks. GitHub takes that a step further by putting everything online so that a team can work on the same project from different places.

For cloud work specifically, this matters a lot. Cloud setups often involve configuration files that control servers, databases, and other resources. If someone makes a mistake in one of those files, version control lets the team find exactly what changed and fix it quickly. GitHub also lets people review each other's changes before anything goes live, which helps catch errors early.

In short, version control is just a safety net. It makes it easier to work as a team, harder to lose work, and faster to fix problems when they happen.

As a developer myself, I have relied on Git and Github so many times throughout the years. It is due to the fact that it is reliable and a industry standard to use this version control.
